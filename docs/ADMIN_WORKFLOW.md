# Administrator workflow

## Intake setup

1. Sign in at `/admin/login` with an allowlisted email magic link.
2. Create the case at `/admin/cases/new` and confirm the one-location scope.
3. Select the common module, one industry module, and all relevant issue modules.
4. Enter known facts with provenance, neutral current profile candidates, custom questions, requested evidence, and a customer-specific introduction.
5. Copy the generated link once, preview it, and send it privately. Regenerate or revoke it if disclosure is suspected.

## Review after submission

1. Move from `신규 접수` to `1차 검토 중`.
2. Confirm the actual business identity and authority before profile conclusions.
3. Reorder and normalize the timeline without changing `customer_raw_response`.
4. Use the comparison matrix to inspect name, address/floor/pin, phone, website, category, account, control, and independence differences.
5. Mark facts as confirmed, customer statement, inference, unknown, or conflicting. Add a source-focused note.
6. Review every hypothesis's supporting facts, contradiction, unknowns, evidence needs, safe action, and non-conclusion.
7. Create easy follow-up requests from suggestions, copy the message, mark it sent, record the response, and resolve or reopen it.
8. Choose A-H only after required conditions, blockers, evidence, risks, included scope, and excluded scope are reviewed.
9. Export a case brief or sanitized structured file when needed. Exports never include intake tokens or private file URLs.

## Status discipline

Use the constrained transitions rather than skipping operational stages. Reopening a customer response changes intake state but does not silently overwrite the prior final payload; the subsequent final submission becomes the new source-shaped record, while administrator audit actions remain.

## Completion and retention

Set the completion date, record the final decision and scope, schedule a retention review, remove unnecessary attachments when appropriate, and handle additional businesses as new cases.
